    Indexing 與 setitem

    簡化版 NumPy 架構不代表把所有 Python semantics 塞進核心資料結構。相反地， descriptor 只保存 storage 與 layout；Python adapter 負責把 user-facing index 轉成 storage coordinate。這樣 C++ kernel 與後續 dispatch 看到的 contract 保持 簡單；Python 端則在 ghost translation 後，繼續使用 Python 的 negative wrap、 slice clipping 與 negative-step normalization。

    數值方法常把 ghost cells 與真正的計算區域放在同一個 allocation。這樣 stencil 與 boundary update 可以直接共享 storage，不必在兩份 array 之間搬資料；但 C++ 看到的是完整 storage，Python 使用者通常想從第一個 body cell 開始數。

    如果 Python index 0 仍直接等於 storage index 0，每段 boundary-condition code 都得手動加上 ghost offset。若只把 pointer 永久往 body 移，negative index、完整 storage slice 與 reversed destination 又會失去原本的基準。需要的不是另一份 buffer，而是一層明確的 coordinate translation。

    沒有 ghost cells 時，Python index 0 與 descriptor coordinate 0 恰好重合。 設定 nghost=3 後，logical_data() 仍是 descriptor origin，但 a[0] 必須代表 第一個 body cell；完成 ghost translation 後，才套用 Python negative-index 與 slice normalization。

    Indexing 的整體架構

    nghost 不修改 logical_data、shape 或 strides。它只在 axis 0 建立 body pointer：

    Text Only
    body() = logical_data() + nghost * stride[0]

    Python adapter 先把 key 正規化成 storage coordinate，再交給原本的 descriptor address rule。Wrapper 先依 assignment form 選擇路徑：

    assignment normalize writer
    scalar RHS + integer key axis 0 加 nghost，再做 negative wrap at()
    sequence RHS + slice key 平移 explicit bounds，再做 slice.compute() TypeBroadcast

    兩條路徑最後都沿同一組 signed strides 找到 address。這裡的 dispatch 只決定 如何解讀 Python key，不會改變 storage allocation、layout 或 descriptor。

    Scalar index

    令 axis 0 storage length 為 \(N\)，ghost count 為 \(G\)。輸入 index \(i\) 先 shift：

    Text Only
    shifted = i + G
require -N <= shifted < N
storage_index = shifted < 0 ? shifted + N : shifted

    最後由 at() 套用 signed stride：

    Text Only
    address = logical_data + storage_index * stride[0]

    以 N=8, G=3 為例：-3 到 storage 0（first ghost），0 到 storage 3 （first body），-4 經 Python wrap 到 storage 7。

    所以完整 valid interval 是 [-N-G, N-G)，不只是 [-G, nbody)。Scalar getitem 與 setitem 共用相同的 normalize_index()；多維 tuple 只有 axis 0 加上 nghost，其他 axes 僅處理一般 negative index。

    一個容易忽略的 alias

    -11 → -8 → 0，因此它和 -3 指向同一個 storage cell。這不是額外的 ghost 規則，而是 shift 之後仍套用完整 Python negative-index normalization 的結果。

    Slice assignment

    Slice 不能當成兩個 scalar indices 分別處理。None、negative step 與 clipping 都屬於 Python slice semantics，必須先完整 normalize；之後才能沿 destination 的 signed strides 寫入。

    先看一個具體結果：explicit bounds [-2:0] 是 body-relative，所以會選到兩個 ghost cells；[0:1] 則從第一個 body cell 開始。

    Python
    import numpy as np
import solvcon

a = solvcon.SimpleArrayFloat64(shape=5, value=0)
a.nghost = 2

a[-2:0] = np.array([10.0, 11.0])
a[0:1] = np.array([20.0])

np.testing.assert_array_equal(a.ndarray, [10, 11, 20, 0, 0])

    每個 axis 先有 storage-wide default slice [0:N:1]。對 axis 0：

    1. Explicit start 與 stop 各加 nghost；None 保持 None。
    2. step 原樣保留。
    3. 呼叫 py::slice.compute(N)，取得 clipped (start, stop, step, length)。
    4. 要求 RHS ndarray 的 rank 與每軸 shape 等於 slice result。
    5. 對每個 slice coordinate \(k\) 計算 destination address。
    \[ \begin{aligned} \operatorname{index}_d &= \operatorname{start}_d + k_d\operatorname{step}_d, \\ \operatorname{offset} &= \sum_d \operatorname{index}_d\operatorname{stride}[d], \\ \operatorname{dst} &= \operatorname{logical\_data} + \operatorname{offset}. \end{aligned} \]

    Destination stride 可以是負數；RHS ndarray 也依自己的 signed byte strides 走訪。None bounds 不會加 nghost，因此 a[::2] 與 a[::-1] 作用於完整 storage，ghost cells 也包含在內。

    支援範圍

    目前 Python wrapper 有意維持較小的 surface：

    • Scalar RHS 支援 integer key 或全 integer tuple。
    • Sequence RHS 支援 slice、tuple of slices、以及最多一個 ellipsis。
    • Slice RHS 必須同 rank、每軸 shape 完全相同；這裡沒有 NumPy singleton broadcasting。
    • 不支援 scalar-to-slice、mixed integer/slice tuple、newaxis、fancy index 或 boolean index。
    • __getitem__ 目前也沒有 slice getter。

    這些限制屬於 Python setitem parser。無論前面經過 scalar 或 slice normalization，最後仍回到第一章同一條 address rule： logical_data + Σ index[d] · stride[d]。
